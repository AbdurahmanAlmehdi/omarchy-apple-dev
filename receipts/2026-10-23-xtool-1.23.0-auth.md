# xtool 1.23.0 pin: `xtool auth` no longer fails with -80045 (issue #78)

Date: 2026-10-23. Host: x86_64 Debian 12 (not Arch), Swift 6.4.0 (swift.org release tarball), libimobiledevice 1.4.0 with
libplist 2.7.0, libimobiledevice-glue 1.3.2, libusbmuxd 2.1.1 and libtatsu 1.0.5 built from release tarballs into a private
prefix. Debian 12 ships libimobiledevice 1.3.0, which lacks `idevice_events_subscribe`; Arch ships 1.4.

## What changed
- `joshuaswarren/xtool@omarchy/1.23.0-fixes` is upstream tag 1.23.0 plus our ten commits, cherry-picked with `-x`, in order.
  Nine applied cleanly. `build-server: map SwiftPM's symlinked source paths ...` (xtool-org/xtool#302) conflicted in
  `Sources/XToolSupport/DevBSPCommand.swift` (upstream renamed `.standardInput` to `.currentStandardInput`); the resolution keeps
  our `BSPSourcePathProxy().run(...)` call. Tip: `f300489f3a3fddbd9fb598ba6cf69eb24a494527`.
- xtool-org/xtool#290, #291, #292, #293, #295 and #302 are still open upstream on 2026-10-23, so none could be dropped.
- Upstream fix for the reported error: xtool-org/xtool#337 (`gsa: fix login using mismatched client-info`, merged 2026-10-13),
  first released in 1.22.2; it is in 1.23.0.
- `install-toolchain.sh` pin: `XTOOL_SHA` moves from `f0a1f90e...` to `f300489f...`. README version table updated.

## Evidence
`swift build -c release --product xtool -Xswiftc -no-toolchain-stdlib-rpath` finished with "Build complete" for both commits
(f300489f: 337 s; f0a1f90e, the old pin: 355 s). Same machine, same network, same made-up Apple ID and password (random
values generated for the run, never an account of ours, masked here):

| xtool commit | `xtool auth login -u <made-up-id> -p <made-up-pw> -m password` |
|---|---|
| f0a1f90e (1.20.1 based, old pin) | `Error: This action cannot be completed at this time. (-80045)` |
| f300489f (1.23.0 based, new pin) | `Error: Your account information was entered incorrectly. (-20970)` |

The new error is Apple's invalid-credentials answer. The old one rejected the request before it looked at the credentials.
